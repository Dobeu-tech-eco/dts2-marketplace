# autopilot - section 6, son mode

## 6. Son mode
`/dts2-harness:autopilot --son <stamp>/<lane>` is one headless lane of a `dpp` run, started by the head in the lane's worktree. Everything in sections 0 to 5a applies unchanged; `discipline.md` and the run and ship skills are the rules, this section only says what differs.
- Input: `.harness/runs/<stamp>/<lane>/brief.md` (lane id, lease epoch, branch `dts2/<stamp>/lane-<lane>`, file set, task list, `MAX_BUNDLE`), which the head builds with `python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/briefs.py" son-brief <manifest> --lane <lane> --epoch <epoch> --out <brief.md>`; the brief and this file are all a son reads of this skill. The discipline, roster and probe arrive in the system prompt (`briefs.py prefix`), not as files to read. Output: `status.json`, `report.md` and the receipts in that run dir, nothing else under `.harness/`; `harness-lock.py --role son` refuses the shared records, which the head folds on completion.
- Builder branches: inside a son, builder `<n>` gets `git worktree add "$DTS2_BUILDERS_DIR/<n>" -b dts2/<stamp>/lane-<lane>-b<n> dts2/<stamp>/lane-<lane>` (`DTS2_BUILDERS_DIR` is the one directory outside the repo that `lanes.py spawn` creates and the sandbox lets the son write; a worktree anywhere else is refused), and the son merges builder branches into `dts2/<stamp>/lane-<lane>`, not `dts2/<stamp>/main`.
- A son runs under the sandbox, a tool allowlist and a deny hook: it may push only its own lane branch (or its builder branches), never merges, never runs `lanes.py merge-go`, `merge-go-step`, `merge-target` or `gc-restore` (by any path, `python3 lanes.py` or the file itself), never reads credentials, and never writes `.claude/`, `.mcp.json`, `.git/hooks` or `merge-go.md`. A denial is a park, not something to route around.
- A question goes to `questions/<n>.md` in the run dir and the son waits for the head's answer file; the head answers alone. A son talks to the head, never the user.
- The son takes a step through to `pr-open` and stops there: it never runs section 3 step 4 or step 6. The head grants `merge-go.md`, runs `gh pr merge` (through the merge guard) and the post-merge walkthrough, and serialises merges across lanes.
- A son never runs setup or onboard, never writes `.harness/lessons.md` (lessons go in `report.md` for the head), never starts another son, and never runs `dpp`.
- A son stamps its heartbeat at every turn boundary with `python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/lanes.py" heartbeat <stamp> --lane <lane>`. A son sets its phase only through the script, never by writing `status.json`: `lanes.py heartbeat <stamp> --lane <lane> --status pr-open` while it waits for `merge-go.md`, then `--status done`, `--status blocked` or `--status incomplete` (with `--reason "..."`) at the end. `lanes.py status` marks a lane with no heartbeat for `stall_minutes` stalled, unless its son process is still running; the head never edits `status.json` itself.
